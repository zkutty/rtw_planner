## Module Dependencies

### Core Application (`app.py`)
- Imports from `lib/` for all core functionality
- Uses Flask for web framework
- Handles routing and API endpoints

### Library Modules (`lib/`)
- `seats_aero_partner_api.py` - Primary API client (used by app.py)
- `db_reader.py` - Database interface (used by app.py)
- `csv_availability_reader.py` - CSV data interface
- `interactive_rtw_planner.py` - Core RTW planning logic
  - Imports `csv_availability_reader` (same directory)
- `airport_data.py` - Airport utilities (standalone)

### Scripts (`scripts/`)
- All scripts import from `lib/` using `from lib.module import ...`
- Scripts are meant to be run from project root: `python scripts/script_name.py`

### Deployment (`deployment/`)
- Deployment tools import from `deployment/` using relative imports
- `render.yaml` references `scripts/build_database.py` in build command

## Import Patterns

### From Application Code
```python
from lib.seats_aero_partner_api import SeatsAeroPartnerAPI
from lib.db_reader import DatabaseReader
from lib.interactive_rtw_planner import InteractiveRTWPlanner
```

### From Scripts
```python
from lib.seats_aero_client import SeatsAeroClient
from lib.csv_availability_reader import CSVSeatsAeroClient
```

### Within lib/ Directory
```python
# Files in lib/ can import from each other directly
from csv_availability_reader import CSVAvailabilityReader
```

## Data Files

- `flights.db` - SQLite database (generated, gitignored)
- `seats.aero qantas Export.csv` - CSV export data (large file)
- `airports.dat` - OpenFlights airport database

## Configuration Files

- `.env` - Environment variables (gitignored)
- `requirements.txt` - Python dependencies
- `.gitignore` - Git ignore patterns
